# Мультисессия, очередь и параллельные сессии

Зафиксировано: поведение очереди при нескольких сессиях **оставляем как есть**.
Параллельные сессии — сознательно **не делаем** сейчас (см. оценку в конце).

## Что умеет сейчас

- **Одна генерация за раз.** Машину держит одна сессия (`TaskManager.activeTaskId`).
  Это ограничение Pi/модели, не интерфейса.
- **Очередь на сессию.** Сообщение, отправленное в сессию, пока занята другая,
  кладётся в `task.pendingPrompts` этой сессии и **уходит автоматически**, когда
  занятая сессия завершается. Порядок — FIFO, несколько сообщений разрешены.
  (проверено `tests/queue-http.test.mjs`: «a prompt queued for another session goes
  out when the busy session finishes».)
- **«Отправить сейчас»** в баннере очереди может «вклиниться» только в сессию,
  которая **владеет машиной** (она прерывает свой текущий ход). Для сессии, которая
  ждёт, это означало бы вторую параллельную генерацию, поэтому:
  - кнопка остаётся нажимаемой (мёртвая кнопка ничего не объясняет);
  - на нажатие показывается `Сейчас нельзя: идёт сессия «X». Сообщение отправится
    само, когда она завершится.`;
  - сообщение при этом **не теряется** и остаётся в очереди;
  - в строке очереди видно `— ждёт «X»`.

## Что пришлось бы менять для настоящей параллели

«Параллельно» здесь — не потоки (Node однопоточный, генерацию делает внешний
процесс), а **слоты модели + независимые агенты**.

Уже готово к параллели:

- отдельный процесс Pi на сессию (`this.runtimes` — `Map(taskId → { pi })`);
- события/история и workspace — уже на сессию.

Мешает и потребует работы:

1. `activeTaskId: string` → набор активных слотов с лимитом N. Затронуты
   `#pump`/`#pumpOnce`, резервирование слота (`reservedElsewhere`),
   `sendPendingNow`, `#interruptGeneration`, гейты cancel/compact.
2. `#admit` — глобальный мьютекс на приём → мьютекс на слот.
3. `getBusyStatus()` → «занято K из N слотов» (локально — по `/slots` llama.cpp,
   для удалённого провайдера — свои лимиты).
4. Локальная модель: `-np N` (слоты) и память — `-c` делится между слотами,
   KV-кэш растёт ×N. На 27B это и есть практический потолок, а не код.
5. UI: несколько «Работает» одновременно, activity-баннер, `stopTarget`,
   «Отправить сейчас» — уже по слоту.
6. Метрики/нагрузка; guard’ы рестарта модели/сервера (сейчас требуют простоя).

Оценка:

- **Фаза 1 — параллель на удалённой модели/провайдере.** Средний рефактор: снять
  единый `activeTaskId` до лимита N и починить ~25 точек, плюс UI-статусы.
  Скрытая цена — множество инвариантов «есть один активный».
- **Фаза 2 — параллель на локальной модели.** Существеннее и упирается в железо
  (слоты + VRAM); `busy`-гейт становится «K из N», появляется деградация
  пропускной способности.

Вывод: без слотов модели «параллельные Pi» просто встанут в очередь у модели.
Реальную параллельность даёт либо `-np N` на локальной (и хватает VRAM), либо
удалённый провайдер, допускающий конкурентные запросы.
