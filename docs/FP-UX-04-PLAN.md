# FP-UX-04 — компактный выбор плана со сканированием проекта

**Режим: IMPLEMENTATION.**

Основа — текущий локальный HEAD после `7134eec` и существующий диалог Follow Plan.

**Цель:** сохранить привычный системный выбор файла, дополнительно предоставить поиск Markdown-файлов текущего проекта по отдельной кнопке и предотвратить случайное подключение документов, не являющихся планами.

## FP-UX-04A — интерфейс выбора

Переработать существующий диалог, не создавать отдельный экран файлового менеджера.

### Стартовое состояние

Отображать:

- Заголовок «Следование плану».
- Краткое описание функции.
- Название текущего проекта.
- Основную кнопку «Сканировать проект».
- Дополнительную кнопку «Открыть файл».
- Краткий текст «План не подключён».

Не отображать список папок и результаты предыдущего сканирования до явного запроса.

### Сканирование

По нажатию «Сканировать проект» выполнить рекурсивный поиск `.md` и `.markdown` внутри текущего серверного workspace.

Результат — плоский список файлов, не список директорий.

Каждая строка содержит имя, относительный путь и результат предварительной классификации, когда он известен.

Добавить поиск по имени/пути, повторное сканирование и пустые состояния.

Не сканировать при открытии окна, переключении чатов, каждой SSE-отрисовке или каждом изменении текста поиска.

### Мобильная компоновка

На Android использовать компактную адаптивную панель.

- Верхняя часть с заголовком и закрытием.
- Поиск и список с прокруткой.
- Высота строки не менее 48 dp.
- Ограничение ширины текста и ellipsis для длинных имён.
- Относительный путь под именем файла.
- Нижняя зона действий остаётся доступной.
- Учитывать системные Insets и клавиатуру.
- Не создавать вложенных модальных окон для просмотра папок.

На Desktop использовать компактное окно нормальной ширины, без чрезмерных вертикальных отступов.

## FP-UX-04B — серверное обнаружение файлов

Реализовать или адаптировать отдельный read-only API сканирования.

Предлагаемый маршрут:

`POST /api/tasks/:id/plan/scan`

Сканирование выполняется по серверному workspace соответствующей сессии.

Защитные ограничения:

- Разрешать только относительные пути внутри workspace.
- Проверять реальные пути, включая Windows junction и symlink.
- Не обходить ссылки, выходящие за пределы проекта.
- Исключать служебные каталоги `.git`, `node_modules`, `.gradle`, `build`, `dist`, `.local` и временные каталоги TaskBridge по умолчанию.
- Поддерживать ограничение глубины, количества результатов и времени сканирования.
- Возвращать признак частичного результата при достижении лимитов.
- Не читать целиком содержимое всех Markdown-файлов.
- Не обращаться к Pi и не создавать Run при сканировании.
- Не кешировать содержимое выбранного файла как источник истины для будущего attach.

Содержимое конкретного файла читать только при выборе и проверке. Перед фактическим подключением повторно проверять актуальный путь и файл.

## FP-UX-04C — выбор с устройства

Сохранить существующую платформенную логику:

- Desktop: Windows FileDialog.
- Android: SAF OpenDocument.
- Web: стандартный input type=file.

Фильтр: `.md`, `.markdown`.

Для файла из проекта Desktop — подключение оригинала по относительному пути, если это безопасно.

Для файла с телефона или другого устройства — передача содержимого на сервер через существующий механизм загрузки и подтверждение назначения.

Не передавать клиентский абсолютный путь как доверенный серверный путь.

Не изменять существующий контракт защиты от перезаписи, включая `PLAN_FILE_EXISTS` и `PLAN_ALREADY_ATTACHED`.

## FP-UX-04D — валидация выбранного файла

После выбора отображать промежуточную карточку.

Проверить:

1. Существование, размер, доступность и кодировку.
2. Границы workspace.
3. Управляемый формат `taskbridge_plan: 1`, когда он присутствует.
4. Наличие цели и хотя бы одного исполнимого шага.
5. Уникальные ID, поддерживаемые статусы и валидную ревизию.
6. Наличие критериев и допустимых результатов для завершённых шагов.
7. Отсутствие критических ошибок парсинга.

Разделять результаты:

- `VALID_MANAGED` — готов к подключению.
- `CONVERTIBLE` — похож на план, но требует предварительного преобразования.
- `NOT_A_PLAN` — обычный документ или недостаточно информации.
- `INVALID` — технически непригоден.

Для `CONVERTIBLE` показывать предварительный просмотр будущего управляемого файла. Не преобразовывать его автоматически, не удалять исходный текст без явного подтверждения. Использовать существующую CAS-защиту и один итоговый активный файл.

Не считать `README.md`, `AGENTS.md` или иной Markdown-документ планом только из-за наличия пронумерованного списка.

## FP-UX-04E — опциональная ИИ-проверка

Добавить дополнительное действие «Проверить с помощью ИИ» для выбранного файла.

Проверка должна:

- работать по явному запросу пользователя;
- не запускать Follow Plan;
- не запускать инструменты, способные изменить проект;
- иметь лимиты на объём передаваемого текста и количество запросов;
- объяснять, почему файл похож или не похож на план;
- не переписывать содержимое автоматически;
- не заменять структурную проверку;
- учитывать конфиденциальность при использовании облачного провайдера.

Если модель недоступна, обычное подключение валидного управляемого плана продолжает работать.

## FP-UX-04F — отмена и удаление

Разделить три действия.

**«Отменить выбор»** — сбрасывает ещё не подключённый файл и возвращает диалог в стартовое состояние. Ничего на диске не удаляется.

**«Отключить следование»** — снимает активную привязку через существующий Detach, оставляя файл в проекте. После подтверждённого сервером отключения интерфейс возвращается в стартовое состояние.

При активном ходе соблюдать существующие STOP/pause и отмену поздних событий. Не отсоединять план так, чтобы оставался бесконтрольный автоматический цикл.

**«Удалить файл с сервера»** — отдельное потенциально опасное действие. Не объединять с отключением Follow Plan. Разрешать только при явном подтверждении и проверке прав/границ workspace. Для исходных файлов проекта лучше не показывать это действие в основном интерфейсе.

Отмена выбора, отключение плана и удаление файла не должны быть синонимами.

## Ограничения

Не изменять PlanFollower, checkpoint, Runs, CommandCoordinator, QueuePump, SSE и алгоритм STOP без воспроизведённого дефекта.

Не сканировать файловую систему телефона вместо серверного проекта.

Не запускать модель при выборе, сканировании или подключении плана.

Не трогать рабочий TaskBridge, Strata, пользовательские Pi-сессии и конфигурацию.

Делать небольшие отдельные коммиты:

1. Backend discovery.
2. Web/KMP список и выбор.
3. Валидация и импорт.
4. Приёмочные тесты.

**Definition of Done:** пользователь одним нажатием получает Markdown-файлы проекта, быстро находит нужный, видит вердикт валидации и подключает только подходящий план. Альтернативный системный выбор файла остаётся доступным. Отмена или отключение возвращают интерфейс в исходное состояние, не удаляя файл случайно.
