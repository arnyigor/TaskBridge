Веб-запуск модели реализуем на существующем RuntimeManager, однако сейчас отключён в конфигурации и не имеет отдельного API/кнопки. Команду NO VISION из указанного launch.txt нельзя использовать без исправления.

Дополнительные ограничения:

- Вложение без текста нельзя отправить: текст обязателен и в UI, и в API.
- Боковая кнопка SEND отправляет только текст; вложения учитывает основной редактор.
- Лимит 25 MiB относится ко всему JSON. Base64 добавляет примерно треть объёма, поэтому реальный суммарный предел файлов — чуть меньше 18,75 MiB. Ранней проверки размера и прогресса загрузки нет.
- Файлы в общем проекте хранятся в одной `.taskbridge-input`. При `useWorktree:false` одинаковые имена могут конфликтовать и между сессиями.
- Факт загрузки PDF/DOCX/картинки не означает, что модель умеет понимать содержимое. Pi получает текстовую подсказку с путями; дальнейшее чтение зависит от инструментов и возможностей модели.

## Модель и веб-запуск

На момент проверки `/health` возвращал OK, а `/props` сообщал `vision:false` и контекст 65536. Значит, текущий экземпляр сервера не поддерживает анализ картинок. Отображение картинки в браузере — отдельная функция и само по себе vision не включает.

В [launch.txt](G:/AIModels/llamacpp/launch.txt) есть два профиля:

| Профиль | Контекст | Особенности |
| --- | --- | --- |
| NO VISION | 8192 | `--no-mmproj`, KV f16, reasoning budget 6144, отключён prompt cache |
| VISION | 33792 | `-mm .../mmproj-BF16.gguf`, KV q4_0, prompt cache включён |

Исполняемый файл, GGUF и mmproj по указанным путям существуют. Профиль NO VISION содержит неподдерживаемый установленным бинарником `--cuda-visible-devices`: команда `llama-server.exe --cuda-visible-devices 0 --help` завершилась с кодом 1 и `invalid argument`. В этом профиле уже есть `--device CUDA0`; лишний флаг необходимо убрать. Полный запуск обоих профилей и их размещение в VRAM не проверялись.

В глобальном описании модели Pi указан contextWindow 65536 и maxTokens 16384; явное поле input с поддержкой image отсутствует. После запуска любого профиля из launch.txt описание возможностей Pi нужно согласовать с реальным сервером. Иначе шкала контекста и момент compaction будут ориентироваться на другой предел. Для NO VISION стоит пересмотреть бюджет рассуждений 6144 при контексте всего 8192.

Существующая основа:

- [RuntimeManager.ensureRunning](G:/Android/AndroidStudioProjects/Taskbridge/src/runtime-manager.mjs:41) проверяет health, запускает процесс скрыто, пишет лог и ожидает готовность до 120 секунд.
- [config.json](G:/Android/AndroidStudioProjects/Taskbridge/config.json:17): managed.enabled=false, команда не задана.
- Новая задача вызывает ensureRunning; [продолжение чата](G:/Android/AndroidStudioProjects/Taskbridge/src/task-manager.mjs:532) только проверяет isReady и при выключенной модели отказывает.
- `/api/info` отдаёт готовность/занятость, отдельного маршрута запуска нет.
- Ошибка запуска/раннее завершение процесса не прерывает ожидание немедленно: пользователь может ждать весь таймаут вместо конкретной ошибки.

Предлагаемая реализация:

1. Два структурированных серверных профиля: текст и vision. Хранить executable, args, cwd, ожидаемые возможности и таймаут; не исполнять произвольную команду, присланную браузером.
2. API состояния и запуска: STOPPED → STARTING → READY/BUSY либо ERROR, PID, активный профиль, последние строки ошибки. Повторное нажатие должно ждать тот же запуск, а не создавать второй процесс.
3. В шапке кнопка «Запустить модель», выбор профиля и статус загрузки. Отправка сообщения может использовать тот же механизм автозапуска как в новой, так и в старой сессии.
4. Уже работающий внешний сервер распознавать отдельно. Переключение профиля не должно незаметно останавливать чужой процесс или активную генерацию.
5. Проверять capabilities и реальный размер контекста; при выборе картинки в текстовом профиле объяснять необходимость vision.
6. Рано показывать ошибку exit/spawn и сохранять лог; запуск exe выполнять без shell, с отдельными аргументами и windowsHide.

Это запускает llama-server на уже включённом ПК с работающим TaskBridge. Для включения самого ПК или запуска выключенного TaskBridge понадобится отдельный механизм.

## Приоритеты улучшений

### 1. Завершить обмен файлами

- Ввести attachmentId, исходное имя, проверенный размер/MIME, направление и привязку к сообщению; хранить файлы под уникальными именами.
- Сделать плашку кликабельной: «Открыть» и «Скачать», превью растровых картинок, текст/code preview, PDF preview; ZIP и офисные форматы сначала скачивать без обещания визуального просмотра.
- Добавить безопасный Markdown со ссылками, картинками и таблицами; локальные ссылки разрешать в пределах workspace.
- Сделать явный реестр результатов агента. Ответ должен содержать карточки файлов независимо от того, каким инструментом файл создан.
- Сохранять отдельную версию вложения, чтобы старое сообщение продолжало открывать прежнее содержимое. Подготовленные файлы отклонённой отправки удалять; прежние файлы не трогать.
- Проверять число файлов, фактический размер, base64 и допустимые имена до сохранения; показывать ограничения до отправки. Для больших файлов перейти на потоковую загрузку с прогрессом.

Критерии готовности: TXT/PNG/PDF/ZIP в первом и следующем сообщении; русские имена, пробелы, одинаковые имена, нулевой файл, превышение лимита; скачивание с исходным именем; старые ссылки после перезапуска; отказ RPC без порчи ранее отправленного файла.

### 2. Веб-запуск и согласование профиля модели

Реализовать описанный единый механизм старта и проверить холодный запуск, повторный клик, ошибочный путь, занятую модель, существующий внешний процесс, продолжение сохранённого чата и реальное распознавание картинки в vision-профиле.

### 3. Доступ к управлению ПК и безопасный просмотр файлов

Сервис слушает 0.0.0.0 без авторизации, API позволяет управлять агентом и читать workspace. Добавить pairing телефона/сессию доступа и проверку Origin на изменяющих запросах. Это особенно актуально до расширения управления процессами из браузера.

HTML-файлы сейчас выдаются как text/html с origin TaskBridge. Предпросмотр HTML должен быть изолирован (sandbox без доступа к API или отдельный origin), либо такие файлы следует скачивать. Добавить nosniff и корректные download-заголовки. Для файлов проекта нужен запрет выдачи секретов, а не только проверка выхода за каталог.

### 4. Проверяемый результат работы с проектом

В текущем зарегистрированном проекте useWorktree=false и verification пустой. Агент работает прямо в исходной папке, а SUCCEEDED означает завершение без ошибок модели, но не прохождение тестов.

- Для задач с изменениями использовать отдельный worktree и показывать diff перед применением.
- Настроить npm run check и npm test как проверки этого проекта.
- Разделить «Ответ завершён» и «Проверки пройдены».
- Исправить сбор diff: [git diff](G:/Android/AndroidStudioProjects/Taskbridge/src/git.mjs:61) без дополнительных опций не включает новые untracked-файлы и staged-изменения. Список changedFiles может содержать файл, которого нет в diff.patch. Для передачи полного результата нужно учитывать оба случая и бинарные файлы.

### 5. Удобство ежедневной работы

Черновики сообщений и выбранных файлов при переключении сессий; копирование ответа/кода; поиск и переименование сессий; явное состояние очереди при занятой модели; уведомление о завершении на телефоне; контроль размера истории и очистка сохранённых результатов. История/восстановление/SSE уже имеют тесты, поэтому сначала выгоднее закрыть перечисленные пробелы в файлах и runtime.
