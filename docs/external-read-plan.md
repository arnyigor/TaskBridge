# External Read Directories + EXT-REMOTE-01

Основание: два приложенных пользователем плана External Read Directories и удалённого файлового браузера KMP. Второе приложение обрывается в таблице тестов раздела 12; отсутствующее продолжение не считается согласованным контрактом.

## Границы безопасности

- NTFS читает только сервер TaskBridge. Android/KMP отправляет команды по авторизованному API; SMB и Android storage permissions для файлов Windows не нужны.
- `browse`, `preview`, `agent-read`, `attach-file` — независимые полномочия. Ни просмотр, ни preview, ни одноразовое вложение не выдают агенту доступ ко всему каталогу.
- В MVP новые полномочия подтверждает локальный оператор Windows. LAN-клиент создаёт только запрос. `platform.kind == desktop` не доказывает локальность.
- Агент получает виртуальные `rootId` + относительный путь; абсолютные пути и содержимое не попадают в публичные ошибки/аудит.
- Политика передачи данных выбранной модели/MCP проверяется отдельно от права локального чтения.
- Read-only сервис не является OS-level песочницей для bash/MCP/Pi. `realpath → open` не обеспечивает строгую защиту от гонок с junction.

## Очередность и проверка

### EXT-01 — модель разрешений проекта

Реализована базовая конфигурация: `src/external-files/config.mjs`, проверка при `TaskManager.init()`, пустой список в примере конфигурации. Без настройки существующие проекты не меняются. Включение только явным `enabled: true`; уникальные root ids; ограниченный allowlist расширений; канонизация; запрет корней дисков, профиля целиком, системных/секретных каталогов и специальных Windows-путей. Построение новой конфигурации увеличивает ревизию, no-op её сохраняет; публикация и сохранение изменений будут обязанностью авторизованного API.

Проверка: `node --test --test-force-exit tests/external-read-policy.test.mjs`.

Ограничение текущего этапа: настроенный каталог обязан существовать при запуске сервера. Отдельный статус сохранённого, но недоступного каталога требуется реализовать до UI; неправильная конфигурация сейчас останавливает запуск до восстановления сессий. Никакие внешние файлы агенту ещё не выдаются.

### EXT-02 — безопасные операции чтения (следующий этап)

Добавить policy/resolver/list/reader/audit. Проверять относительные сегменты, приватные пути, ADS, symlink/junction на каждом вызове; ограничения размера до и во время чтения. Не подключать чтение к агенту до проверки NTFS и гонок. Для строгой защиты исследовать проверку открытого handle / изоляцию ОС; не считать предварительный realpath доказательством.

Приёмка: разрешённые текст/изображения читаются; traversal, ссылки наружу, секреты, запрещённые расширения и превышение лимита отклоняются. Отзыв блокирует следующий вызов. Отдельные Windows-тесты EXT-T06/T07/T19 обязательны.

### EXT-03 / EXT-04 — Pi и Plan

Loopback API с отдельным токеном Pi-процесса, привязанным к сессии/проекту. Два инструмента `taskbridge_external_list/open`, без самостоятельного доступа расширения к диску. Подключение независимо от approvals; текущие права проверяются при каждом вызове. Явный allowlist Plan; проверка реальной vision-модели и размера последующих запросов.

### EXT-05 — API разрешений и запросов

Сохранение и аудит, ревизии/409, идемпотентность команд, локальное подтверждение и отзыв. Статусы запросов только серверные: PENDING/APPROVED/DENIED/EXPIRED/CANCELLED. Токены Pi не дают права управления.

### EXT-REMOTE-01 — обязательный серверный браузер перед полноценным KMP UI

Проектные маршруты:

- `GET /api/projects/:id/remote-files/roots`
- `GET /api/projects/:id/remote-files/browse?rootId=...&path=...`
- `GET /api/projects/:id/remote-files/preview`
- `GET /api/projects/:id/external-read`
- `GET/POST /api/projects/:id/external-read/requests`
- `POST /api/projects/:id/external-read/requests/:requestId/decision` (только локально)
- `POST /api/tasks/:taskId/remote-files/prepare-attachment`

Не перечислять все диски. Новый неизвестный каталог запрашивается без раскрытия содержимого до подтверждения. Пагинация, bounded preview (ориентир 2 МиБ), отмена, лимиты запросов. Вложение — серверный снимок через UploadStore, без скачивания на Android и обратной загрузки; токен ограничен проектом, чатом и инициатором. Проверить неизменность источника при создании снимка.

Приёмка: независимость четырёх полномочий, LAN не подтверждает запрос, отозванные права действуют немедленно, чужой чат не принимает токен, preview не обходит политику и размер.

### EXT-06 — Web/KMP

Только после рабочего серверного контракта. Отдельный RemoteFilesController и экран, API-модели; не переносить файловую логику в ChatScreen/ProjectWorkspace. Навигация по rootId/относительным путям; Narrow/Wide сохраняют проектный контекст. Защита от устаревших ответов; offline отключает операции; опрос PENDING только при видимом экране; без долговременного кэша содержимого/ChatPersistence. Различать сохранённое разрешение, доступность каталога и отказ политики.

«С телефона» использует существующий SAF/upload; «С компьютера» — серверный браузер. Проверить API URL/сериализацию, навигацию/отмену, статусы запросов, offline, пагинацию, конфликты ревизий, отсутствие файла в долговременном кэше.

### EXT-07 — ограниченный поиск

Поиск по имени, предел глубины/числа записей/времени, сортировка по дате/типу. При отсутствии результата сообщать проверенную область; отсутствие прав объяснять без повторяющихся отказов.

## Финальная приёмка

Проверки EXT-T01–EXT-T20 из исходного плана, дополнительные проверки полномочий браузера и снимков. Затем серверная регрессия, `npm run check`, KMP `:shared:jvmTest` и реальные Android/Desktop сценарии. Unit-тесты конфигурации не доказывают работоспособность чтения, транспорта Pi, визуального анализа или UI.
