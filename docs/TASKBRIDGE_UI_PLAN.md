# TaskBridge KMP — доработки UI

> Сверка с кодом на 2026-09-26: [статус реализации, пробелы и результаты исправления чата](TASKBRIDGE_STATUS_2026-09-26.md). Чекбоксы ниже отражают исходный план; фактическая реализация местами уже ушла вперёд.

Документ по результатам разбора текущего Desktop-клиента (светлая тема, окно ~1880 px). Дополняет `TASKBRIDGE_ROADMAP.md`: часть пунктов (статусы, активность, очередь, steer/follow-up) зависит от этапов 2–4 роадмапа — такие пункты помечены **[API]**.

## Часть 1. Анализ текущего состояния

### 1.1 Что уже хорошо

- Двухпанельная схема «сессии слева — чат справа» подходит для задачи.
- Текст ассистента хорошо читается: ширина колонки, межстрочный интервал, инлайн-код в чипах.
- Действия агента свёрнуты в сводки («Выполнил 16 команд», «Изменил 7 файлов»), а не выводятся простынёй.
- Сдержанная палитра с фиолетовым акцентом, выделение активной сессии заметное, но спокойное.

### 1.2 Баги вёрстки

| # | Проблема | Где |
|---|---|---|
| B1 | Кнопка отправки обрезана правым краем окна | composer |
| B2 | Последние строки ответа уходят под поле ввода — у списка нет нижнего отступа | лента сообщений |
| B3 | FAB «Новая сессия» перекрывает последние строки списка | боковая панель |
| B4 | Composer растянут на всю ширину, сообщения — в центральной колонке | экран сессии |
| B5 | Заголовок обрезан посреди слова без многоточия | шапка сессии |
| B6 | Вставка картинки из буфера не работает | composer |
| B7 | Дублирующий список файлов («портянка») в конце ответа | лента |
| B8 | Сырые английские ошибки («Operation aborted before provider attempt.», «stdout maxBuffer length exceeded») | лента, список |

### 1.3 Боковая панель

- **Статусы неоднозначны.** Зелёная точка почти у всех сессий, включая недельной давности. Не видно, кто работает, кто ждёт, кто упал — а это главная задача менеджера.
- **Избыточность.** Остановленная: серая точка + чип «Остановлена». Ошибка: красная точка + красный текст + красный чип. У большинства строк чипа нет → разная высота строк.
- **Нет текущей активности** работающей сессии (что делает, сколько времени).
- **Модель на каждой строке** занимает целую строку и почти везде одинаковая.
- **Заголовки — сырой первый промпт** с опечатками; на 82 сессиях по ним трудно ориентироваться.
- **Смешанные форматы времени и языки:** «54 мин», «10:55», «вчера», «23 Sep».
- **Низкая плотность:** строка ~70 px, видно ~13 сессий из 82; нет разделения на активные и архив.
- **Шапка:** переключатель темы нужен редко; кнопка «Обновить» говорит о том, что список не живой.
- **Меню ⋮ на каждой строке** — постоянный визуальный шум.

### 1.4 Экран сессии

- **Шапка без действий:** нет Stop/Resume, закрепления, смены модели, проекта/ветки/worktree, заполненности контекста.
- **Сводки действий слишком тревожные:** строка «Выполнил 16 команд · ошибок: 4» целиком красная, хотя ненулевой код выхода часто нормален.
- **Разный формат строк инструментов:** `git_ro tool: git_ro` дублирует имя и выглядит иначе соседних строк; шеврон «›» мелкий.
- **Ошибка/остановка без объяснения:** кто прервал и что делать дальше — непонятно.
- **Нет времени и длительности у ответов** ассистента (у сообщения пользователя время есть).
- **Широкий экран не используется:** ~350 px пустоты по бокам колонки.
- **Нет кнопки «к последнему»**, ранняя история — только по клику.
- **Composer минимальный:** нет Stop вместо отправки, нет режима steer/follow-up, нет превью вложений.

## Часть 2. План доработок

Оценки — ориентир в вечерах (~3 ч).

### P0. Баги — 1–2 вечера

- [ ] **B1, B4.** Лента и composer в одном `Column` с общей `widthIn(max = ContentMaxWidth)` (≈ 860–920 dp), выровнены по центру. Кнопка отправки внутри колонки.
- [ ] **B2.** Нижний `contentPadding` у `LazyColumn` = высота composer (измерять через `onSizeChanged`, хранить в state) + 16 dp.
- [ ] **B3.** Убрать FAB из области списка: кнопка «+» в шапке панели сессий + `Ctrl+N`. Если FAB остаётся — нижний `contentPadding` списка на его высоту.
- [ ] **B5.** Заголовок: `maxLines = 1`, `TextOverflow.Ellipsis`, полный текст в тултипе (Desktop) / по долгому нажатию (Android).
- [ ] **B6. Вставка картинки из буфера.**
  - Desktop: `onPreviewKeyEvent` на `Ctrl+V` → чтение AWT-буфера (`Toolkit.getDefaultToolkit().systemClipboard`, `DataFlavor.imageFlavor` и `javaFileListFlavor`) → вложение; если в буфере текст — обычная вставка.
  - Android: приём контента в текстовом поле (content receiver API Compose Foundation — сверить с версией) + вставка из буфера через `ClipboardManager`.
- [ ] **B7.** Список изменённых файлов показывается только в карточке «Изменил N файлов»; текстовый дубль в конце ответа не выводится (если это текст самой модели — фильтровать на уровне рендера либо поправить системный промпт/правило агента).
- [ ] **B8.** Словарь ошибок `код/шаблон → русский текст + действие`. Сырое сообщение — в раскрывающемся «Подробнее» с кнопкой копирования. Минимум:

  | Сырой текст | Показ | Действие |
  |---|---|---|
  | `Operation aborted before provider attempt` | «Запрос прерван до обращения к модели» + причина (Stop / idle / рестарт сервера) | «Продолжить» |
  | `stdout maxBuffer length exceeded` | «Вывод команды слишком большой» | «Подробнее» (и починить на бэкенде: `spawn` с потоковым чтением) |
  | обрыв соединения | «Нет связи с ПК» | «Повторить» |

- [ ] **Единый форматтер времени** (русская локаль):

  | Когда | Формат |
  |---|---|
  | < 1 мин | «сейчас» |
  | сегодня | «22:10» |
  | вчера | «вчера» |
  | текущий год | «23 сен» |
  | раньше | «23.09.25» |

  Длительность работы — отдельно: «2:13», «1 ч 05 мин».

**Готово, когда:** на окнах 1280 / 1920 / 2560 px и на телефоне ничего не обрезано и не перекрыто; вставка скриншота `Ctrl+V` создаёт вложение; ни одной английской ошибки в UI.

### P1. Боковая панель — 2–3 вечера

#### Единая модель статусов [API]

Один индикатор на строку, без дублирующего чипа.

| Состояние runtime / задачи | Цвет | Вид в строке |
|---|---|---|
| `WORKING` | синий | пульсирующая точка + строка активности |
| `WAITING_USER` | янтарный | точка + «Нужно подтверждение» |
| `WORKING` + `waiting_model` | синий приглушённый | «В очереди к модели: 2» |
| `IDLE` / `DONE` | нейтральный (без заливки) | — |
| `SLEEPING` / `STOPPED` / `RESTORABLE` | серый контур | — |
| `FAILED` | красный | одна строка причины (из словаря B8) |

- [ ] Компонент `StatusDot(state)` + анимация пульса только для `WORKING`.
- [ ] Строка активности для `WORKING`: `иконка · pytest tests/world_model · 2:13`, обновляется из потока `/api/stream`. **[API]**

#### Структура списка

- [ ] Секции:
  1. **Требуют внимания** — `WAITING_USER`, `FAILED`;
  2. **Работают** — `WORKING`;
  3. **Недавние** — за 7 дней;
  4. **Архив** — свёрнута по умолчанию.
  Счётчики у секций; пустые секции скрываются.
- [ ] Закреплённые сессии — сверху своей секции со значком 📌. **[API]**
- [ ] Группировка по проекту сохраняется как уровень выше секций (если проектов больше одного) или как фильтр.

#### Строка сессии

- [ ] Компактная строка ~48 dp, две линии:
  - линия 1: `StatusDot` · заголовок · время справа;
  - линия 2: активность / причина ошибки / модель (только если отличается от модели по умолчанию).
- [ ] Меню ⋮ — только при наведении или фокусе (Desktop); на Android — долгое нажатие.
- [ ] Переключатель плотности «Компактно / Обычно» в настройках.

#### Заголовки

- [ ] Автозаголовок: эвристика (первое предложение, до 60 символов, нормализация пробелов после знаков препинания) → при желании один дешёвый вызов модели для короткого названия.
- [ ] Переименование: двойной клик (Desktop) / пункт меню (Android). **[API]** `PATCH /api/tasks/:id {title}`.
- [ ] Исходный промпт — в тултипе.

#### Шапка панели

- [ ] Оставить: поиск, фильтр, «+ Новая сессия».
- [ ] Убрать: «Обновить» (список живой через `/api/stream`), переключатель темы (в настройки).
- [ ] Фильтры-чипы под поиском: «Активные», «С ошибками», «Закреплённые», выбор проекта.
- [ ] Индикатор подключения к ПК внизу панели: `● LAN · 12 мс` / `● Tailscale · 85 мс` / `○ Нет связи`.

**Готово, когда:** по списку за секунду видно, какие агенты работают, какие ждут и какие упали; на экране помещается 20+ сессий в компактном режиме.

### P2. Экран сессии — 3–4 вечера

#### Шапка

- [ ] Слева: короткий заголовок; под ним `статус · проект · ветка/worktree · модель`.
- [ ] Модель кликабельна → выбор модели. **[API]**
- [x] Быстрый селектор по образцу Pi Desktop: каталог из кэша при открытии, обновление в фоне, свёрнутые провайдеры со счётчиками, поиск по провайдеру/ID/названию, индикатор переключения и явная ошибка. Пункт выше остаётся открытым для ручной проверки клика по метке на Desktop/Android.
- [ ] Полоска заполненности контекста с процентом в тултипе. **[API]**
- [ ] Справа: основная кнопка по состоянию (`Stop` в `WORKING`/`WAITING_USER`, `Продолжить` в `SLEEPING`/`RESTORABLE`/`STOPPED`), 📌, меню (Clone, Compact, Открыть папку, Копировать ID сессии).

#### Строки активности

- [ ] Единый формат: `иконка · что сделано · счётчики · длительность ›`.
- [ ] Иконки по типу: терминал (команды), файл (правки), субагент, git, чтение.
- [ ] Нейтральный цвет строки; ошибки — отдельный красный бейдж с числом.
- [ ] Шеврон крупнее, поворачивается при раскрытии; зона нажатия — вся строка (≥ 40 dp).
- [ ] Одиночный инструмент показывается как `иконка · git_ro · статус`, без дубля `tool: git_ro`.
- [ ] Раскрытие команд: список `команда · код выхода · длительность`, первые 3 строки вывода, «Показать полностью».
- [ ] Раскрытие файлов: `путь · +12 −3`; клик → diff (Desktop — в правой панели P3, Android — отдельный экран).
- [ ] «Размышления» — свёрнуты, приглушённым цветом, с длительностью.

#### Карточка ошибки / остановки

- [ ] Причина по-русски (словарь B8), кто/что остановил (пользователь с устройства X, idle-таймаут, рестарт сервера).
- [ ] Кнопки: «Продолжить», «Подробнее» (сырой текст + копирование).
- [ ] Нейтрально-предупреждающий стиль для остановки пользователем, красный — только для реальных сбоев.

#### Лента

- [ ] Метаданные turn'а мелкой строкой под ответом: `22:14 · 3 мин 12 с · 18.4k токенов`.
- [ ] Метка источника у сообщений пользователя: «с Android», «из терминала». **[API]**
- [ ] Статус своего сообщения: «в очереди», «отправлено». **[API]**
- [ ] Кнопка «↓» с числом новых событий, если пользователь прокрутил вверх; автопрокрутка только когда пользователь внизу.
- [ ] Подгрузка ранней истории при прокрутке к верху (с сохранением позиции).
- [ ] Выделение и копирование текста ответа; копирование блока кода кнопкой.

#### Composer

- [ ] В `WORKING`: кнопка отправки → `Stop`; при вводе текста — переключатель «В очередь» (follow-up) / «Вмешаться» (steer). **[API]**
- [ ] Вложения — чипы с превью над полем, удаление крестиком, размер файла.
- [ ] Drag & drop файлов и картинок в окно (Desktop).
- [ ] `Enter` — отправить, `Shift+Enter` — перенос (настраиваемо).
- [ ] Автовысота поля до ~8 строк, дальше прокрутка.
- [ ] Черновик сохраняется при переключении сессий.

**Готово, когда:** из шапки доступны все действия с сессией; по свёрнутой ленте понятно, что делал агент и где были реальные ошибки; остановка всегда объяснена.

## Часть 3. Порядок и зависимости

```
P0 ──→ P1 ──→ P2 ──┬─→ P3 (Desktop)
                   └─→ P4 (Android)
P5 — параллельно, компоненты выносятся по мере P1–P2
```

Зависимости от бэкенда (`TASKBRIDGE_ROADMAP.md`):

| Пункт UI | Нужен этап роадмапа |
|---|---|
| Строка активности, общий поток статусов | этап 4 (`/api/stream`) |
| Статусы `WAITING_USER`, `SLEEPING`, `RESTORABLE` | этап 3 (state machine) |
| «В очереди к модели» | этап 4 (планировщик) |
| Метка источника, статус отправки | этап 2 (`source`, `clientRequestId`) |
| Переименование, закрепление | `PATCH /api/tasks/:id` |

Пункты P0 и большая часть P1/P2 не зависят от бэкенда и делаются сразу.

## Часть 4. Критерии приёмки

- [ ] Нет обрезанных и перекрытых элементов на 1280 / 1920 / 2560 px и на телефоне.
- [ ] По списку сессий за секунду видно: кто работает, кто ждёт, кто упал.
- [ ] Каждая остановка и ошибка объяснена по-русски и имеет действие.
- [ ] Вставка картинки из буфера работает на Desktop и Android.
- [ ] Все действия с сессией доступны из шапки или меню, без перехода в веб-UI.
- [ ] Скриншот-тесты ключевых состояний зелёные в обеих темах.
