# TaskBridge — переработка глобальной памяти

**Задача:** устранить переполнение хранилища глобальной памяти, сохранить все существующие знания и внедрить масштабируемое управление заметками.

**Приоритет:** P0 для сохранности данных и корректной загрузки памяти; P1 для поиска, консолидации и интерфейса.

**Основное требование:** лимит количества файлов не должен приводить к удалению знаний или отказу в сохранении новой темы. Ограничение контекста LLM должно работать независимо от размера хранилища.

## MEM-00. Найти настоящий источник предупреждения

**Статус:** функционально завершён по решению пользователя. Процесс, модуль, источник лимита, каталог, число тем и политика очистки установлены; см. `global-memory-mem00-diagnosis.md`. Поиск дословного текста не блокирует следующие этапы.

Исходное диагностическое сообщение:

`Глобальная память переполнена: 15 тем сверх лимита 15`

Проверить:

1. Исходники установленного MCP `manage_project_memory`.
2. Его фактический исполняемый модуль и конфигурацию.
3. Значение лимита, действующее в текущем процессе.
4. Число сохранённых и число активных тем.
5. Каталог, к которому применяется ограничение.
6. Выполняется ли проверка при сохранении, чтении, старте сервера или инъекции в контекст.
7. Есть ли автоматическое удаление, обрезка или отказ от записи.
8. Откуда именно TaskBridge получает предупреждение: MCP response, Pi extension, собственный backend или UI.

Особенно проверить, не запущена ли старая копия MCP-сервера после обновления исходников.

**Нельзя:** менять константу `MAX_ACTIVE_PROJECTS` вслепую, пока не определён действующий компонент.

**Результат:** отчёт с точными файлом, функцией, значением лимита, путём хранилища и объяснением причины.

## MEM-01. Защитить существующие данные

**Приоритет:** P0

До миграции или очистки создать проверяемую резервную копию:

- Legacy `persistent_memory/*.md`.
- `pi-memory-md` со всеми проектами и глобальными заметками.
- SQLite-индекса памяти TaskBridge, если используется.
- Метаданных и предложений на консолидацию.
- Конфигурации MCP и Pi memory extension.

### Требования

1. Не изменять оригиналы при инвентаризации.
2. Сохранить структуру каталогов и frontmatter.
3. Записать SHA-256 каждого файла.
4. Проверить восстановление из резервной копии в отдельный каталог.
5. Не выполнять `--force` при переносе.
6. Не удалять legacy-заметки после копирования.

**Готово, если:** все исходные записи можно восстановить побайтово.

## MEM-02. Отменить ограничение на количество хранимых тем

**Приоритет:** P0

Прежнее ограничение вроде `MAX_ACTIVE_PROJECTS = 15` заменить на разделённые лимиты.

### Storage limit

Не устанавливать малый жёсткий лимит количества тем. Допускать накопление сотен и тысяч заметок, сохраняя разумные ограничения на размер одного файла, общий размер хранилища и ресурсы индексирования.

### Injection limit

Сохранить независимый токен-бюджет, ограничивающий объём памяти, передаваемый модели.

### Search limit

Сохранить пагинацию результатов поиска.

**Правильное поведение при переполнении:**

- Новая запись остаётся в хранилище.
- В модель передаются только релевантные записи, помещающиеся в бюджет.
- Остальные доступны поиском.
- Пользователь видит, что именно было пропущено.
- Автоматическая очистка не запускается.

Не решать проблему увеличением токен-бюджета до объёма всей базы.

## MEM-03. Разделить глобальные и проектные знания

**Приоритет:** P0

Перепроверить текущие темы:

- `pfpht2`
- `oh-my-pi`
- `figma`
- `blender`
- `pi-app`
- остальные темы из legacy-хранилища.

Не считать их глобальными только потому, что старый MCP хранит все файлы в одной папке.

### Рекомендуемая классификация

**Global**

Универсальные предпочтения, правила работы агента, общие настройки среды, сквозные технические решения.

**Project**

Архитектура конкретного приложения, пути файлов, ошибки, задачи, решения по конкретному репозиторию.

**Shared**

Знания, применимые нескольким проектам, но не всему окружению.

**Archive**

Устаревшие, заменённые или редко востребованные сведения.

### Правила миграции

- Тему с однозначной принадлежностью проекту переносить в соответствующий проект.
- Неоднозначную тему оставлять на ручное рассмотрение.
- Не выводить принадлежность по названию файла, если содержание противоречит названию.
- Сохранять исходный путь и provenance.
- Не смешивать одноимённые проекты с разными Git-репозиториями.
- Предусмотреть решение конфликтов идентичности между checkout и worktree.

**Результат:** таблица миграции всех существующих тем со статусами `GLOBAL`, `PROJECT`, `SHARED`, `REVIEW`, `ARCHIVE`.

## MEM-04. Устранить расхождение каталогов глобальной памяти

**Приоритет:** P0

В TaskBridge сейчас используется:

`GLOBAL_SCOPE_DIR = '_global'`

При этом `pi-memory-md` позволяет настроить собственный каталог общей памяти, а в его примерах используется `global`.

Необходимо:

1. Определить фактический `localPath` установленного расширения.
2. Прочитать эффективный `memoryDir.globalMemory`.
3. Сверить каталог, который читает Pi, с каталогом, который индексирует TaskBridge.
4. Сделать путь конфигурируемым, а не жёстко зашитым в `_global`.
5. Защититься от выхода пути за пределы memory root.
6. Не объединять два существующих каталога без миграции.
7. Если найдено несколько глобальных каталогов, показать конфликт и предложить безопасный способ разрешения.

**Готово, если:** Pi и TaskBridge читают одни и те же глобальные заметки, а интерфейс явно показывает активный путь.

## MEM-05. Проверить и доработать поиск

**Приоритет:** P1

Использовать существующий SQLite FTS-индекс и механизмы ранжирования, не внедряя сразу отдельную векторную базу.

### Проверить

- Поиск по всем глобальным заметкам.
- Поиск по конкретному проекту.
- Поиск по нескольким выбранным проектам.
- Совместный поиск global + project.
- Русские и английские запросы.
- Составные имена и технические идентификаторы.
- Опечатки и альтернативные названия.
- Устаревшие и заменённые заметки.
- Корректность индекса после переименования и перемещения файлов.
- Пагинацию и общее количество совпадений.

### Исправить ограничения

Не ограничивать глобальный инвентарь первыми 200 файлами. Выдача результатов может оставаться ограниченной, но подсчёт общего числа заметок должен быть полным.

Разделить:

- `totalStored` — сколько записей реально существует.
- `totalActive` — сколько актуальны.
- `matched` — сколько соответствуют запросу.
- `returned` — сколько отдано текущей страницей.
- `injected` — сколько передано модели.

Проверить `globalAvailable` в `TaskManager.searchMemory`: сейчас для определённого сценария используется `globalEntries({limit: 0})`, что возвращает пустой список и не может служить корректным подсчётом.

**Готово, если:** все сохранённые темы доступны через поиск независимо от токен-бюджета инъекции.

## MEM-06. Улучшить выбор знаний для модели

**Приоритет:** P1

Сохранить независимые бюджеты для проектной и глобальной памяти. Текущие 2000/400 токенов использовать как исходную конфигурацию, а не как универсально оптимальный размер.

### Алгоритм

1. Определить активный проект.
2. Получить текущую пользовательскую задачу.
3. Построить ограниченное число поисковых запросов.
4. Найти релевантные проектные записи.
5. Найти релевантные глобальные записи.
6. Исключить дубликаты и superseded-знания.
7. Упорядочить по релевантности, приоритету и актуальности.
8. Заполнить раздельные токен-бюджеты.
9. Передать в контекст выбранные заметки с указанием происхождения.
10. Записать диагностическую статистику доставки.

Не подставлять все глобальные знания в каждый запрос.

### Постоянно доступные знания

Для небольших действительно универсальных правил можно предусмотреть отдельную компактную базовую память. Она не должна автоматически включать список всех проектов или историю всех решений.

### Fallback

Если глобальный поиск недоступен, агент должен продолжить работу без выдуманного контекста, а диагностика — назвать причину сбоя.

**Готово, если:** увеличение хранилища не приводит к пропорциональному увеличению системного промпта.

## MEM-07. Консолидация вместо удаления

**Приоритет:** P1

Использовать существующие механизмы `memory-consolidator.mjs` и `memory-proposals.mjs`, расширив их на глобальную память.

### Функции

- Обнаружение дубликатов.
- Поиск заметок на одну тему.
- Обнаружение противоречащих решений.
- Выявление устаревших записей.
- Объединение нескольких заметок в одну структурированную запись.
- Перенос знания из Global в Project.
- Архивирование.
- Отмена ошибочного архивирования.

### Важно

Все изменения проходят через proposal workflow.

```text
Обнаружен кандидат
       ↓
Предложение на объединение
       ↓
Предпросмотр изменений
       ↓
Проверка конфликтов
       ↓
Подтверждение пользователем
       ↓
Новая версия знания
       ↓
Старые записи отмечены superseded
```

Не выполнять автоматическое безвозвратное удаление даже при превышении бюджета.

Сначала использовать существующую логику Jaccard для кандидатов. При низком качестве можно отдельно проверить FTS/BM25 и модельную проверку сходства. Модель не должна самостоятельно утверждать изменения хранилища.

## MEM-09. Диагностика и метрики

**Приоритет:** P1

Расширить `memory-metrics.mjs`.

Новые показатели:

- `global_stored_notes`
- `global_active_notes`
- `global_archived_notes`
- `global_indexed_notes`
- `global_search_hits`
- `global_injected_notes`
- `global_injected_tokens`
- `global_skipped_notes`
- `global_skipped_tokens`
- `global_sync_failures`
- `memory_conflicts`
- `memory_consolidation_pending`

Разделить проектные и глобальные причины пропуска.

Проверить существующий путь `recordOverflow`: сейчас глобальное переполнение объединяется с общим, но признак глобального overflow при сборке результата может не передаваться, поэтому специализированный счётчик может не отражать ситуацию.

Добавить диагностический ответ, который сообщает, почему конкретная заметка не была использована:

- Нет совпадения с запросом.
- Не помещается в токен-бюджет.
- Заметка устарела.
- Заменена другой заметкой.
- Неподходящая область памяти.
- Ошибка индекса.
- Невозможность чтения файла.

Не записывать приватное содержание заметок в общедоступную телеметрию.

## MEM-10. Безопасная миграция старой памяти

**Приоритет:** P0

Использовать `scripts/import-persistent-memory.mjs` как основу, но не запускать существующий режим `--apply` без аудита.

Проверить:

1. Все старые темы распознаны.
2. Ни одна тема не пропущена.
3. Содержимое сохранено полностью.
4. Созданы правильные целевые пути.
5. Нет конфликтов существующих файлов.
6. Frontmatter содержит корректные description, tags и provenance.
7. Глобальные записи не перенесены ошибочно в проектные.
8. Индекс обновился.
9. Pi действительно обнаруживает новые записи.
10. Старое хранилище осталось без изменений.

Процесс миграции должен поддерживать:

`dry-run → отчет → подтверждение → копирование → проверка → переключение источника → rollback`

Не включать одновременно два независимых writer-механизма. После переключения legacy MCP становится read-only до завершения периода проверки.

## MEM-12. Приёмка на реальных данных

После успешных изолированных тестов:

1. Получить полный перечень текущих тем.
2. Зафиксировать содержимое и контрольные суммы.
3. Провести классификацию Global/Project/Shared.
4. Выполнить миграцию в тестовый каталог.
5. Убедиться, что все темы доступны поиском.
6. Проверить релевантность выбора на задачах Blender, Figma, Pi и других существующих проектов.
7. Убедиться, что знания одного проекта не попадают автоматически в другой.
8. Проверить состав фактически инъектированных знаний.
9. Выполнить обновление индекса и повторный запуск.
10. Только после проверки переключить рабочую конфигурацию на новый источник.

### Definition of Done

- Переполнение по количеству тем устранено.
- Ни один исходный файл не потерян.
- Все темы можно найти.
- Проектные сведения изолированы.
- Глобальные знания подбираются по релевантности.
- Токен-бюджет соблюдается.
- Автоматического удаления нет.
- Консолидация требует подтверждения.
- Пользователь видит причину пропуска заметок.
- Существующий Pi/TaskBridge продолжает работать без регрессий.

## Production deployment — DEP-01…05

Разработка и изолированные тесты приняты пользователем как завершённые. Рабочая установка не заменена. Runbook и точные команды: `MCP_DEPLOYMENT.md`; локальные результаты: `.local/deployment-readiness/`.

- **DEP-01 — NO-GO:** read-only аудит Markdown, каталогов и core.py запросил SACL и LABEL; 128 объектов дали Win32 1314. Требуется SeSecurityPrivilege. Отсутствие метаданных не предполагается; повышения прав/обхода не было.
- **DEP-02 — NO-GO:** настоящее MCP stdio, git, inventory/search/concurrency PASS; реальный tokenizer HTTP400, tokens=None. `.venv`/base Python подтверждены отдельным запуском и fingerprint окружения.
