# low vs medium thinking на реальной Android-задаче

Запрос оператора: «проверить разницу на локальной модели, low vs medium, максимально близко к
реальной работе — рефактор фичи, поиск бага, добавление функционала Android-приложения».

## Что получилось и на чём

- **Локальная модель сейчас не запускается**: `POST /api/local/load {id: "qwen-27b-q3"}` →
  `status: unloaded, failed: true, exitCode: 1`, llama-server отвечает
  `500 {"message":"model name=qwen-27b-q3 failed to load"}`, а файла модели из `models.ini` нет на
  диске (`G:\AIModels\lmstudio\unsloth\` пуст). Поэтому сравнение на локальной модели провести
  нельзя — уровни `off/low/medium` падают одинаково, в ответ пустая ассистентская реплика.
- Сравнение сделано на **deepseek-flash** (та же семья провайдера, что и рабочая сессия оператора:
  окно 204 800, thinking-блоки). Стенд и задание идентичны для обоих прогонов.

## Стенд

`experiments/thinking-level/`:
- `fixture.mjs` копирует настоящий модуль `clients/kmp/core` + `tests/fixtures` в песочницу
  (раскладка как в репозитории, иначе часть тестов красная по среде) и вносит задание:
  **баг** — фильтр «Без проекта» терял сессии без проекта; **функционал** — поиск по id сессии;
  **рефакторинг** — вынести фильтрацию/поиск из `groups()` без изменения публичного API.
- `run-compare.mjs` запускает Pi RPC с `--thinking <level>`, `-ne` (одинаковый набор инструментов,
  без UI-расширений), даёт агенту `TASK.md` и проверяет работу **тестами самого проекта**
  (`./gradlew -p core :client:jvmTest --no-configuration-cache`, `--rerun-tasks` для базовой линии).
- Вердикт: приёмочные тесты зелёные, нет новых падений относительно базы, баг устранён, приёмочный
  файл не изменён (его правка = провал).

## Результат (одна и та же задача)

| | low | medium |
|---|---|---|
| время | **62 с** | 104 с |
| сообщений в сессии | 39 | 64 |
| вызовов инструментов | **18** | 31 |
| input за сессию | 15 755 | 21 553 |
| output за сессию | 4 423 | 8 284 |
| cacheRead | 322 816 | 669 056 |
| thinking ассистента | 5 924 симв. | 15 109 симв. |
| текст ассистента | 1 738 симв. | 2 462 симв. |
| тесты | зелёные | зелёные |
| баг / фича / рефакторинг | сделано | сделано |

Базовая линия в обоих прогонах: 6 красных тестов (2 приёмочных + 4 «средовых»), после работы —
0 приёмочных и 0 новых падений.

**Вывод:** на этой задаче оба уровня решили её одинаково; `medium` обошёлся в ~1,7× времени,
~2,6× thinking и ~2,1× прочитанного кэша без наблюдаемого выигрыша в качестве. Наблюдение в пользу
`low` для рутинных правок, но выборка — один прогон, один класс задач, одна модель; это не
измерение «в среднем».

## Что не проверено

- Локальная модель (файл модели отсутствует) — сравнение локально не проводилось вообще.
- Один прогон на уровень, без повторов: разброс не измерен.
- Задание среднего размера (один файл 396 строк, 3 подзадачи); на большой кодовой базе разница
  может быть иной.

## Как воспроизвести

```
node experiments/thinking-level/run-compare.mjs --provider deepseek --model deepseek-flash --thinking low
node experiments/thinking-level/run-compare.mjs --provider deepseek --model deepseek-flash --thinking medium
```

Отчёты: `.local/thinking-level/{low,medium}-*/report.json` (git-ignored). Для локальной модели —
`--provider llama.cpp --model qwen-27b-q3` после восстановления GGUF из `models.ini`.
