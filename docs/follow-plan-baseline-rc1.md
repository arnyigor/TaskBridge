## Известные ограничения RC1

1. **Windows `FileDialog` — PARTIAL, не PASS.** Диалог открывается кнопкой «Открыть
   файл», но подтвердить его синтетическим вводом в неинтерактивной сессии не
   удалось (три попытки, включая `toFront()/requestFocus()`). Решение после выбора
   покрыто `PickerPathTest`: файл внутри проекта становится относительным путём,
   всё остальное уходит содержимым. Android SAF проверен целиком живьём.
2. **CAS на Windows.** `withPlanWriteLock` сериализует записи внутри одного процесса.
   Окно между проверкой хэша и `rename` только сужено: Windows не даёт файлового
   compare-and-swap, поэтому внешняя правка, попавшая в это окно, может быть
   потеряна. Правка до проверки — не перезаписывается (`PLAN_REVISION_CONFLICT`).
3. **Проверка evidence.** `SYSTEM_VERIFIED` требует `toolCallId` вызова этого хода
   (или Run этой сессии); `kind: "manual"` от модели — не принятие оператора. Всё
   остальное — `MODEL_REPORTED`. Практический вывод: «шаг выполнен» может быть
   заявлением модели, а не фактом; смотреть на уровень подтверждения в панели.
4. **Зависимость от модели.** Автоцикл требует рабочего провайдера; при недоступной
   модели шаг не отправляется, план остаётся на паузе. Проверка ИИ в выборе файла
   необязательна: без модели — `AI_UNAVAILABLE`, подключение валидного плана работает.
5. **Длительность и бюджеты автономной работы.** `maxCycles: 20`, `noProgressLimit: 3`,
   `auditTurnsPerCycle: 1`, `budgetMs: 6 ч` (`src/application/plan-follower.mjs`).
   При исчерпании — `PLAN_BUDGET_EXCEEDED` и пауза. Упавший/отменённый ход или
   рестарт сервера не повторяются автоматически, а переводят план в `PAUSED_REVIEW`.
6. **Отключение не удаляет файл.** Отдельного действия «удалить файл с сервера» нет:
   файл плана — исходный файл проекта.
7. **Браузера папок нет.** Маршрут `/plan/browse` и неиспользуемые помощники выбора
   остались только в API/тестах, UI их не вызывает.
8. **Android — только эмулятор** Pixel 5 API 31, на реальном устройстве не проверялся.
9. **Транспорт.** Follow Plan проверялся на локальном транспорте; через облачный
   relay в этом раунде не перепроверялся.

## Как включить и выключить

Включение (по умолчанию функция выключена в коде и не запускает ничего сама):

1. В `config.json` сервера:
   ```json
   "followPlan": { "enabled": true }
   ```
2. Перезапустить сервер (кнопка «Перезапустить сервер» или
   `node scripts/start-lan.mjs restart`).
3. Проверить: `GET /api/info` → `followPlan.enabled: true` и непустой
   `followPlan.capabilities`; в интерфейсе иконка «По плану» перестала быть серой.
4. Подключить план кнопкой, но **не** нажимать «Начать выполнение»: подключение не
   запускает модель.

Выключение: `"enabled": false` + перезапуск. Читающие маршруты остаются, изменяющие
отказывают (`FOLLOW_PLAN_DISABLED`); уже идущий цикл всегда можно остановить
(`STOP`), и он встанет на разбор.

На этой машине `config.json` уже содержит `"followPlan": { "enabled": true }` — это
состояние оператора, документ его не меняет.

## Возврат к предыдущему baseline

```sh
cd <clone>
git fetch --tags                       # тег — локальный, если push не делался
git worktree add ../TaskBridge-stable taskbridge-stable-2026-10-22
cd ../TaskBridge-stable/clients/kmp && ./gradlew :desktopApp:installPortable
```

- Планы и привязки живут в SQLite сервера. Перед возвратом стоит отключить активные
  планы (`POST /api/tasks/:id/plan/detach`) и убедиться, что нет идущих циклов: старый
  бинарник не знает маршрутов `scan`/`ai-review`, но данные привязок читает тот же.
- `config.json` и `data/` остаются на месте; возврат baseline — это возврат кода и
  пересобранного `TaskBridge.exe`, а не данных.
- Возврат RC1 обратно — `git checkout taskbridge-follow-plan-rc1-2026-10-24` и та же
  пересборка.
