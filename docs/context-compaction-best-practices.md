# Сжатие контекста: практики, источники и что из этого делать в TaskBridge

Ревью практик по внешним источникам (2026-10-30), с привязкой к тому, что уже проверено
на этом проекте. Внешние утверждения помечены источником; всё, что помечено «проверено
здесь», измерено нами (`docs/mcp-compact-audit-2026-10-30.md`, `scripts/pi-compaction-probe.mjs`,
`experiments/compact-00/run-zero-tail.mjs`).

## 1. Рамка: «контекстная инженерия», а не «сжатие любой ценой»

Anthropic формулирует задачу как «найти минимальный набор высокосигнальных токенов, который
максимизирует вероятность нужного результата»; контекст — конечный ресурс с убывающей отдачей
(*Effective context engineering for AI agents*, Anthropic, 2025). Практический вывод: уменьшать
надо не «то, что заметно», а то, что не несёт сигнала, и делать это как можно менее разрушительно.

Порядок рычагов (от безопасного к разрушительному) — он же порядок приоритетов:

| # | Рычаг | Потери | Кто это делает |
|---|---|---|---|
| 1 | Стабильный префикс, который вообще не растёт (промпт, инструкции, схемы инструментов) | нет | все, но требует дисциплины |
| 2 | Ссылки вместо содержимого: файлы, URL, запросы читаются по требованию (JIT) | нет | Claude Code, Gemini CLI |
| 3 | Очистка старых результатов инструментов (tool result clearing) | низкие, вывод можно перечитать | Claude API `context_editing`, Codex, OpenCode |
| 4 | Сжатие истории в сводку (compaction) | средние/высокие | Claude Code/API, Pi, Gemini CLI |
| 5 | Изоляция в субагенте с кратким отчётом | низкие для родителя | Anthropic multi-agent |
| 6 | Новая сессия + handoff-документ | высокие для «болтовни», нулевые для решений | практика harness'ов |

Anthropic прямо называет очистку результатов инструментов «самой безопасной и самой лёгкой формой
компакции», а сжатие — рекомендуемой стратегией для длинных диалогов (там же; Claude Platform docs,
`context_editing`, beta-заголовок `context-management-2025-06-27`: триггер 100K входных токенов,
сохраняются 3 последних вызова инструментов).

## 2. Что это значит для наших цифр

Проверено здесь: после ручного compact у вас остаётся ~46K: сводка 1.5K + **снимок системного
промпта из записи сжатия ~15K** + **сохранённый хвост ~19K** + статика. То есть 93% остатка — это
не сводка. Практики из п.1 ложатся ровно на это:

- хвост — рычаг №4, самый крупный и самый дешёвый в реализации (`keepRecentTokens`; проверено:
  `0` даёт 3.7K на стенде и ≈15–18K на реальной сессии, потому что остаётся снимок);
- снимок — это «стабильный префикс, который внезапно заморожен»: он попадает в «context clash»
  (устаревшие объявления инструментов рядом с текущими), а не только в расход;
- статика (навыки 10.5K символов объявлений, `AGENTS.md` 12.2K) — рычаг №1/№2: описания навыков
  стоят ~100 токенов каждый при прогрессивном раскрытии (Anthropic, Agent Skills), полный текст
  читается по требованию — у нас в контекст попадают все 22 описания всегда.

## 3. Практики, которые стоит перенять (с обоснованием)

1. **Сначала очистка, потом сводка.** Чистить выводы `bash`/`gradle`/`read` старше N токенов,
   оставляя запись «инструмент вызывался, результат архивирован со ссылкой», — без вызова модели
   (Anthropic context editing; Codex — truncation на записи 10KB; OpenCode — `prune()` старше 40K).
   У нас это CMP-04 и он выгоднее CMP-03 по соотношению эффект/риск.
2. **Сжимать в логических точках, а не на пределе.** Claude Code советует `/compact` на 70–80%
   окна; overflow-сжатие — аварийный режим. Сейчас TaskBridge сжимает по лимиту и по кнопке; кнопка
   должна показывать «сколько останется» и предупреждать о цене.
3. **Сказать, что сохранять.** `customInstructions` у Pi RPC уже есть; Claude Code даёт
   «Compact Instructions» в CLAUDE.md и `/compact focus on ...`. Наш аналог — секция
   «Compaction Instructions» в проектном `AGENTS.md` + передача фокуса из UI. Дешёво, проверяемо.
4. **Структурированная сводка с проверкой полноты.** Anthropic: «начинайте с максимизации recall,
   потом убирайте лишнее»; только Gemini CLI реально проверяет recall вторым проходом, все прочие
   генерируют один раз и надеются. У Pi формат из 6 секций (Goal/Constraints/Progress/Decisions/
   Next Steps/Critical Context). Предложение аудита — контрольные вопросы до/после сжатия — это и
   есть проверка recall; для Follow Plan обязательна (id плана, шаг, подтверждённые checkpoint).
5. **Изоляция вместо сжатия.** Субагент с чистым окном и кратким отчётом (рекомендация Anthropic:
   1000–2000 токенов) — у TaskBridge есть инструмент `subagent`; исследование не должно оставлять
   50 выводов `grep` в основном окне.
6. **Артефакты вместо памяти диалога.** Практика long-horizon harness'ов: состояние задачи в файлах
   (план, прогресс, результаты тестов), а сессия — расходник. У нас это `docs/*` + Follow Plan;
   после сжатия агент должен читать план с диска, а не полагаться на сводку.
7. **Стабильный префикс ради кэша.** Неизменяемое — вперёд, менять редко: cached read стоит ~10%
   от обычного входа (Claude Code cost guide). Отсюда следствие: каждый compact ломает кэш префикса —
   поэтому частые мелкие сжатия дороже одного большого.
8. **Меньше инструментов, чем кажется нужным.** «Самодостаточные, однозначные, экономные» описания
   (Anthropic); Pi даёт `--tools`, `--exclude-tools`, адаптер — `excludeTools` и режимы
   direct/deferred/codemode/hidden. У нас в снимке 36 инструментов = 34.9K символов; отключение
   ненужных MCP — самый быстрый способ уменьшить и контекст, и снимок.
9. **Не сжимать маленькие и средние сессии.** Проверено здесь: при `keepRecentTokens: 20000` сессия
   ~31K вообще не сжимается (`Nothing to compact (session too small)`), потому что хвост «съедает»
   всю историю. Правило: полное сжатие только для больших сессий, для средних — очистка инструментов.
10. **Измерять провайдером, а не оценкой.** `chars/4` — эвристика Pi; выводы о выигрыше делать по
    `usage.input` и `cacheRead`, иначе «экономия» остаётся оценкой. У нас есть `breakdown`, но
    `providerInputTokens` пока `null` — это честный пробел, а не ноль.
11. **Не удалять историю.** Pi хранит исходные записи и лишь не проецирует их в контекст; TaskBridge
    обязан сохранять пользовательскую историю независимо от сжатия (уже так).
12. **Осторожно с «просто большим окном».** Chroma (Context Rot, 18 моделей) показывает деградацию
    точности с ростом входа задолго до заполнения окна; needle-in-haystack это не выявляет.
    Практический вывод: 1M окно — не замена сжатию.

## 4. Чего не делать

- Не переносить в KMP свою суммаризацию: политика должна быть серверной, клиенты — только UI
  (в силе вывод первого аудита).
- Не сжимать «в ноль» без сводки покрывающей весь участок: `firstKeptEntryId: null` с чужой сводкой
  тихо теряет сообщение (проверено по коду Pi: значение используется дословно).
- Не менять `compaction.*` глобально ради эксперимента: это влияет на все ваши сессии и применяется
  только к новым процессам Pi.
- Не верить «мгновенности»: OMP-подобные shake/snapcompact быстрые, но требуют vision-модели или
  архива с восстановлением; критерием должен быть сохранённый рабочий статус, а не время.

## 5. Что из этого уже есть и чего нет в TaskBridge

| Практика | Статус |
|---|---|
| Разделение измеренного и оценочного | есть (`breakdown`, `usage.source`, `snapshotTokens`) |
| Единый реестр инструментов и `pending_restart` | есть (CMP-01) |
| Очистка результатов инструментов (CMP-04) | нет |
| Полное ручное сжатие (CMP-03) | механизм Pi проверен, в TaskBridge не включён (нужно решение по agent dir) |
| Проверка качества сводки, контрольные вопросы (CMP-05) | нет |
| Фокус сжатия из UI (`customInstructions`) | сервер умеет, UI не предлагает |
| Секция «Compaction Instructions» в `AGENTS.md` | нет |
| Провайдерские `input`/`cacheRead` в отчёте | нет (`providerInputTokens: null`) |

## 6. Источники

- Anthropic, *Effective context engineering for AI agents* (2025) — рамка, три уровня компакции,
  очистка результатов инструментов как «самая безопасная форма», субагенты, JIT-retrieval.
  Страница блокирует извлечение, поэтому читана через несколько независимых конспектов, включая
  сравнительный обзор практик агентов (lin-guanguo.github.io, «Anthropic Guidance — LLM Agent
  Research») и разбор dreaming.press «Context Engineering the Anthropic Way».
- Anthropic, *Effective harnesses for long-running agents* — handoff между контекстами, прогресс в
  артефактах, ограничения компакции (тоже только через конспекты).
- Claude Platform docs, *Context editing* (`clear_tool_uses_20250919`, `clear_thinking_20251015`,
  триггер/keep, beta `context-management-2025-06-27`) и *Compaction* — извлечение блокировано,
  цифры по конспектам.
- Claude Code docs (best practices, `/compact`, `/context`, cost guide) — через зеркало
  docs.qcode.cc (окно 1M, `/compact` на 70–80%, `CLAUDE.md` перечитывается после сжатия, стабильный
  префикс ради кэша) и обзор agentic-engineer.com (цена резерва авто-сжатия, деградация после
  повторных сжатий).
- Chroma, *Context Rot* (research.trychroma.com/context-rot; страница блокирует извлечение) —
  деградация у 18 моделей с ростом входа, по conspectus tinyfish.ai и particula.tech.
- Pi 1.4.0 (установленная): `docs/compaction.md`, `docs/sessions.md`, код `dist/core/compaction`,
  `dist/core/session-manager.js` — проверено локально, это первичный источник для наших решений.
