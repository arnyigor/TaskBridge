# P0-AB — A/B доставки инструкций (legacy против hook)

Итог серии 2026-10-21. Сравнение только по одному фактору — способу доставки
инструкций хода: `legacy` дописывает блок в первое сообщение, `hook` кладёт секцию
`turn_instructions` в system-промпт через Pi-расширение на каждом ходу. Дерево кода,
сценарии, фикстура и настройки прогона одинаковые.

- Сценариев: 8 (`ue-filmmakers`, `houdini`, `missing-nuke`, `ambiguous-ocean`,
  `negative-lookup`, `find-and-fix`, `complex-compare`, `bulk-count`), по одному
  прогону на ячейку.
- Модели: `deepseek/deepseek-flash` (облако) и `strata/qwen3.8-flash-next-iq3_s`
  (локальная, Q3, одна модель на движке).
- Таймаут на сценарий: 120 с.
- Сырые данные: `.local/bench/p1/` (`REPORT-cloud.md`, `REPORT-local.md`, `runs/`).

## Результаты

| Метрика | Облако legacy | Облако hook | Локальная legacy | Локальная hook |
| --- | --- | --- | --- | --- |
| Успешных сценариев | 8/8 | 8/8 | 7/8 | 8/8 |
| Вызовов на прогон | 4.875 | 5.375 | 6.75 | 5.25 |
| Лишних вызовов | 2.5 | 2.875 | 4.375 | 2.75 |
| Время, с | 16.0 | 15.7 | 44.0 | 32.0 |
| Токенов на прогон | 13 606 | 15 733 | 17 265 | 13 683 |
| Записей без запроса | 0 | 0 | 0 | 0 |
| Точность профиля | 1.0 | 1.0 | 1.0 | 1.0 |
| Источник профиля | `prompt` 8/8 | `system-section` 8/8 | `prompt` 8/8 | `system-section` 8/8 |
| Путей вне фикстуры | 1 | 7 | 12 | 2 |

## Что подтверждено

1. **Механизм hook работает.** Во всех 16 hook-прогонах профиль читается из
   system-секции Pi (`profileSource=system-section`), в legacy — из текста первого
   сообщения (`prompt`). Точность профиля 1.0 во всех четырёх ячейках, то есть
   профиль выбирается верно и доезжает до модели.
2. **Качество не хуже.** На облаке 8/8 против 8/8. На локальной модели hook 8/8,
   legacy 7/8 — единственный провал legacy это таймаут 120 с на `find-and-fix`
   (модель не ответила), а не ошибка ответа.
3. **Записи без запроса — 0** в обеих политиках и на обеих моделях.
4. **На локальной модели hook эффективнее**: вызовов −22 %, времени −27 %,
   токенов −21 %, при более высоком качестве.
5. **На облаке разницы нет**: время одинаковое, вызовов у hook на 1 больше за серию.

## Что не подтверждено и почему это важно

- **Один прогон на ячейку.** Числа по времени и вызовам — направление, а не
  статистика. Разница в 0.5 вызова на облаке — шум.
- **Герметичность не обеспечена.** Агент выходит за пределы фикстуры: 1 и 7 путей
  вне её на облаке, 12 и 2 на локальной модели. Прогоны, где ответ подтвердился
  только вне рабочей копии, оценкой отвергаются, но полностью исключить влияние
  посторонних данных нельзя. Для строгих серий нужен OS-sandbox (отдельный
  WSL-дистрибутив: он был поднят и снят по решению оператора из-за стоимости).
- **Метрика «утверждения без подтверждения» шумит.** Различия (облако 3→1,
  локальная 1→3) — в основном артефакт проверки по подстрокам: легитимный счёт
  («6 видео», полученное из списка `06.Intro.mp4`) не находится в выводе, потому
  что число там склеено с именем файла. Выводы по этой метрике делать нельзя.
- **`negative-lookup` с таймаутом** остаётся `RUNNING` в записанных данных:
  раннер не отменяет задачу, это известный дефект, он не исправлялся.
- Q3/Q4 и Medium/High не сравнивались: на движке одна локальная модель.

## Отдельные наблюдения (не метрики, а факты прогона)

1. **Выход за пределы фикстуры.** Агент действительно читает данные вне
   синтетического проекта: пути вне рабочей копии — облако 1 / 7, локальная модель
   12 / 2 (legacy / hook). Прогон, где ответ подтвердился только вне фикстуры,
   оценкой отвергается (`foundOnlyOutside`), но полностью исключить влияние
   посторонних данных нельзя. Диагностика `externalPaths` сохранена для будущих серий.
2. **Один таймаут 120 с** — локальная модель, `legacy`, сценарий `find-and-fix`:
   задание не завершилось, ответа нет, в записанных данных осталось `RUNNING`.
   Это дефект стабильности локальной модели и раннера (задача не отменяется по
   таймауту), а не ошибка ответа. Он же тянет вверх среднее время legacy
   (44,0 с против 32,0 с в hook): без него разрыв меньше.
3. **Незапрошенные изменения файлов** сейчас проверяются только по вызовам
   `write/edit/apply_patch`. `bash` тоже может менять файлы, поэтому для
   следующей версии нужен манифест файловой системы до/после — инфраструктура
   для этого уже не требуется.

## Как это формулировать публично

> В предварительном сравнении на восьми сценариях локальная Qwen3.8 Flash Next с
> `hook` использовала меньше вызовов инструментов, токенов и времени, чем с
> `legacy`. Доставка инструкций подтверждена. Результаты производительности
> требуют дополнительной валидации.

Не публиковать «ускоряет Qwen на 27 %»: это разница двух средних по одному
прогону на сценарий.

## Вердикт

`GO` для механизма hook: доставка инструкций через `before_agent_start` работает,
качество не хуже legacy, на локальной модели дешевле и быстрее, записей без запроса
нет. `NO-GO` для публикации чисел скорости как результата: n=1 на ячейку и нет
изоляции. Для решения «включать ли hook» данных достаточно.

### Рекомендуемая конфигурация

`config.example.json` использует `pi.turnInstructions.mode: "hook"` для новых
установок. Требуется поставляемое расширение
`pi-extension/taskbridge-turn-instructions.js`; без него сервер явно отклоняет
ход с `TURN_INSTRUCTIONS_UNAVAILABLE`, а не отправляет запрос без инструкций.

Для совместимости существующих установок отсутствие настройки по-прежнему
означает `legacy`; существующий `config.json` автоматически не изменяется.
Явное значение `legacy` сохраняет старый механизм. Переменная окружения
`TASKBRIDGE_TURN_INSTRUCTIONS` имеет приоритет над конфигурацией.

WSL, Docker и reverse tunnel для этого сравнения не требуются (поднимались и сняты
по решению оператора). Строгие будущие серии — Q3 против Q4 и Medium против High —
полезнее делать напрямую через Strata на заданиях с автопроверкой, без файловых
инструментов и без второй инфраструктуры.
