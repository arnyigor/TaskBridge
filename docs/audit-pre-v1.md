## Что проверено как корректное

- `machine()` устойчив к подделке: `clientAddress` доверяет `X-Forwarded-For`
  только если peer — loopback, а встроенный прокси дописывает реальный адрес
  последним (`src/proxy.mjs`); LAN-режим держит приложение на `127.0.0.1`.
- Изоляция путей: `containedFile` использует `realpath`, отсекает `..`/абсолютные,
  блокирует приватные имена (`.env`, `config.json`, `server-auth.json`, `*.pem`).
- Облако не достаёт до исполнения: `CLOUD_ALLOWED` не содержит `/shell`, `/run`,
  `/open` — спаренный облачный клиент отклоняется.
- CSRF/Origin: `checkOrigin` (JSON content-type + `Sec-Fetch-Site`/`Origin`==`Host`).
- Нет инъекции shell-строк: Windows-open идёт через env в фиксированный
  `Start-Process`, скрипты/команды — через `execFile` (argv), не через shell-строку.
- Рендер markdown/UI XSS-безопасен: DOMPurify; `highlightText` экранирует перед
  `innerHTML`; результаты/заметки — через `textContent`.
- Секреты: `config.json` (боевой `tb_machine_…`) гитигнорится и не в трекинге;
  `npm run check` (аудит секретов) — чисто.

## Известные ограничения (после релиза)

- Экспозиция исполнения при выключенной авторизации (см. #1) — по умолчанию
  доверенная LAN; для строгости включить auth.
- Параллельные сессии не поддерживаются (одна генерация; см.
  `docs/multi-session-queues.md`).
- `ownAddresses` не переживает смену IP без перезапуска (#5).
- Защита от «старого shell + нового app.js» покрывает только новые привязки (#5).
