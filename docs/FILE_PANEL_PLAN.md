# Просмотр файлов: док-панель справа (эталон — DeepSeek harness)

Дата: 2026-10-20. Основание: текущий `FileViewer` открывается модальным диалогом по центру
экрана, из-за чего чат полностью теряется из виду, а второй файл открыть рядом нельзя.

## 1. Что делает DeepSeek harness (разобрано по скриншоту)

| Элемент | Поведение |
|---|---|
| Панель | Прижата к правому краю окна на всю высоту, слева от неё остаётся живой чат, который сужается |
| Полоса вкладок | Сверху: `PRODUCT_GAPS.md`, `README.md` + кнопка `+`, у активной вкладки свой фон, у каждой — `×` |
| Шапка файла | Вторая строка: полный путь (`F:\3D\...\README.md`), справа — режим просмотра и действия |
| Режим | `Markdown ⌄` — «рендер» ↔ «исходник» для `.md`; для кода режим не нужен |
| Действия | Закрыть панель (`×`), развернуть, открыть внешним приложением |
| Ширина | Панель не на всю половину окна, а ~40–45% ширины, чат остаётся читаемым || Ссылки внутри файла | Открываются в новой вкладке той же панели, а не сбрасывают текущий файл |

Выводы для нас: панель — это **док справа**, а не диалог. Диалог по центру оправдан только
там, где док физически не влезает — на телефоне.

## 2. Что есть в TaskBridge сейчас

`clients/kmp/shared/src/commonMain/kotlin/ru/arny/taskbridge/ui/chat/FileViewer.kt` (252 строки):

- `FileTarget` — три вида: `Workspace(path, line, endLine)`, `Attachment(id, name)`, `Artifact(name)`.
- Закрытое состояние `Loaded`: `Text` (обрезка до 300 КБ), `Binary`, `Picture`, `Failed`.
- `FileViewer(target, session, platform, onDismiss, onOpenPath)` — читает файл через API,
  рисует его внутри `AdaptiveSheet`: **диалог по центру** (широкое окно) или `ModalBottomSheet` (телефон).
- Внутри уже есть всё, что нужно панели: подсветка кода (`highlight`/`languageOfFile`),
  рендер Markdown (`MarkdownView` + `LocalOpenFile` для ссылок), просмотр картинки,
  кнопки «Открыть в приложении» / «Показать в папке» (desktop) и «Копировать».
- Вызов — из `ChatScreen.kt`: одно `rememberSaveable` состояние `viewing: FileTarget?` и один
  `FileViewer` в конце композиции. Второй файл заменяет первый, история открытий не сохраняется.

Итого переделывать чтение и рендер не нужно: не хватает **оболочки** (док + вкладки + режим + ширина)
и того, чтобы рендер был вынесен из диалога и переиспользован.

## 3. Целевое поведение (спецификация)

### 3.1 Где какая оболочка

| Ширина области чата | Оболочка |
|---|---|
| ≥ 700 dp (десктоп, планшет, ландшафт телефона) | док справа: `Row { чат (weight 1f) | разделитель 7 dp | панель (width) }` |
| < 700 dp (телефон) | как сейчас: `ModalBottomSheet` |

Порог 700 dp выбран по факту: окно 1180 dp минус список сессий 360 dp = 820 dp области чата,
панель 440 dp оставляет 380 dp на чат — читаемо. Порог `App.kt` (840 dp) для этого не годится:
на штатном размере окна панель бы никогда не включалась.

### 3.2 Вкладки

- Открытие файла из чата (чип файла, ссылка в ответе, `FileList`, артефакт) добавляет вкладку.
- Идентичность вкладки — сам файл: путь для `Workspace`, `id` для `Attachment`, имя для `Artifact`.
  Повторное открытие того же файла не создаёт дубль, а активирует существующую вкладку
  и обновляет диапазон строк (переход `README.md#L120-L140` после `README.md` работает).
- `×` на вкладке закрывает её; активной становится соседняя справа, иначе слева.
- `×` в шапке закрывает панель целиком (все вкладки).
- Полоса вкладок прокручивается, и активная вкладка всегда подкручивается в видимую часть:
  файл, открытый по ссылке из середины документа, не остаётся за правым краем.
- Док показывается, только когда есть хотя бы одна вкладка.

### 3.3 Шапка и режим

- Строка 1: имя файла во вкладке; строка 2: полный путь и служебная подпись
  (размер, «показано начало», «строки 120–140»).
- Для `.md`: переключатель `Просмотр` / `Текст` (рендер ↔ исходник с подсветкой).
  Для остальных файлов переключатель не показывается: там всегда исходник.
- Действия: `Обновить` (перечитать файл), `Ещё` → «Копировать путь», «Открыть в приложении»,
  «Показать в папке» (две последние — только на десктопе).
- Ссылка внутри Markdown-файла открывает новый файл **в новой вкладке** той же панели.

### 3.4 Ширина и сохранение

- Ширина меняется перетаскиванием разделителя; предел — `[360 dp, 70% области чата]`.
- Ширина сохраняется между запусками (`settings.filePanelWidth`, ключ `filePanel.width`),
  по умолчанию 440 dp. Мусор в настройке (0, строка, отрицательное) → значение по умолчанию.
- Разделитель: полоса 7 dp, курсор-«рука» при наведении (в common-коде нет resize-курсора).

### 3.5 Клавиатура

- `Esc`: закрыть активную вкладку → если вкладок нет, прежнее поведение (подтверждение STOP).
  Известное ограничение: на десктопе `Window.onPreviewKeyEvent` в `desktopApp/main.kt`
  перехватывает `Esc` раньше контента и делает `navigator.pop()`. Порядок «панель → STOP → назад»
  требует правки `App.kt`/`main.kt` и вынесен в фазу 4.

## 4. Реализация по шагам

### Фаза 1 — вынести рендер файла из диалога

`FileViewer.kt`:

1. `FileTarget` получает `identity` (`w:<path>` / `a:<id>` / `r:<name>`) — ключ вкладки.
2. Сериализация цели вынесена в `toFields()` / `targetFromFields()`, чтобы ими пользовались
   и `FileTargetSaver` (одна цель), и saver вкладок (список).
3. `Loaded` и `looksBinary` — `internal` (нужны панели).
4. Новое: `FileViewState` (`loaded`, `notice`, `reloadKey`, `reload()`, `setNotice()`),
   `rememberFileViewState(target, session)` и `loadFile(target, session)` — один путь чтения
   для диалога и панели, включая ручное «Обновить».
5. Новое: `fileInfoLine(target, loaded)` — подпись (размер / обрезка / диапазон строк).
   Попутно исправлен приоритет операторов: раньше при обрезанном файле диапазон строк
   терялся (`a + if (cut) … else "" + range`).
6. Новое: `FileBody(target, loaded, platform, markdown, onOpenPath)` — всё «тело» файла:
   спиннер, ошибка, картинка, «это не текст», Markdown-рендер, код с номерами строк.
7. `FileViewer` (диалог/шит) остаётся тем же по поведению, но собирается из 4–6.

### Фаза 2 — сама панель

Новый файл `ui/chat/FilePanel.kt`:

- `FileTabs` — состояние: список целей + активный индекс; `open` (дедуп по `identity`),
  `select`, `close(i)` (с пересчётом активного), `closeActive`, `closeAll`.
- `FileTabsSaver` — `rememberSaveable` для списка вкладок (выживает пересоздание Activity).
- `FilePanel(tabs, session, platform, onClose, onOpenPath)` — `Surface`:
  полоса вкладок (горизонтальный скролл, `×` на каждой, `×` панели справа),
  шапка (путь + подпись + режим + действия), тело в `verticalScroll` с `FileBody`.
- `PanelSplitter(width, onWidth, onRelease, min, max)` — `draggable` по горизонтали,
  ширина через `rememberUpdatedState`, чтобы жест не держал устаревшее значение.

### Фаза 3 — подключить в чат

`ChatScreen.kt`:

- `viewing: FileTarget?` → `fileTabs: FileTabs` (`rememberSaveable(taskId, FileTabsSaver)`),
  `openFile(target)` — единая точка входа для чипов, ссылок, `FileList` и артефактов.
- Корень: `BoxWithConstraints` + `Row`: чат (`weight 1f`) + при `maxWidth ≥ 700.dp` и непустых
  вкладках — `PanelSplitter` и `FilePanel`; иначе `FileViewer` как шит.
- Ширина панели: `mutableStateOf(settings.filePanelWidth)` (с проверкой диапазона),
  запись в настройки — на `onDragStopped`.
- `Esc`-обработчик переносится с `Column` на внешний контейнер, чтобы он видел и панель.

`AppSettings` (`core/client/.../settings/Connection.kt`): `filePanelWidth: Int`.

### Фаза 4 — не входит в эту итерацию (кандидаты)

1. Порядок `Esc` на десктопе: сначала закрыть панель, потом STOP, потом `navigator.pop()`
   (правка `App.kt`/`main.kt`, где сейчас `Esc` забирает окно).
2. Подсветка строк из `#L120-L140` внутри файла (нужен построчный рендер кода, а не один `Text`).
3. Кнопка `+` в полосе вкладок: файловый браузер рабочей папки
   (`session.workspaceFiles()` уже существует и используется композером).
4. Автообновление открытого файла, когда агент его меняет (слушать tool-события хода).
5. «Скачать»/«Открыть» для бинарных файлов в панели (сейчас это делает только шит).
6. Запоминание набора вкладок между запусками приложения.
7. Та же панель для web-клиента (`web/app.js`), чтобы поведение совпадало.

## 5. Библиотеки: почему ничего не добавляем

Проверено по зависимостям `clients/kmp/gradle/libs.versions.toml` (Compose MP 1.12.1,
material3 1.12.0-alpha03): всё нужное — `draggable`, `rememberDraggableState`,
`horizontalScroll`, `DropdownMenu`, `VerticalDivider`, `pointerHoverIcon` — есть в уже
подключённых `compose.foundation`/`material3`. Свой рендер Markdown и подсветка кода в проекте
уже есть; сторонний Markdown/CodeViewer дал бы вторую реализацию рядом с существующей
и расхождение в оформлении ответов чата и файлов. `androidHelpers`/внешние KMP-библиотеки
для этой задачи не требуются.

## 7. Риски

- `rememberDraggableState` с устаревшим `width` в замыкании → жест «залипает». Лечится
  `rememberUpdatedState` (учтено в `PanelSplitter`).
- Потеря `Esc`-подтверждения STOP: условие `dialog == null` сохранено, но обработчик
  переехал с колонки чата на общий контейнер — проверять руками вместе с панелью.
- Панель на узком планшете съедает чат: порог 700 dp и предел 70% ширины.
- Сохранение ширины пишется только на `onDragStopped`, а не на каждый кадр (иначе
  SharedPreferences/prefs дёргаются на каждом движении мыши).
