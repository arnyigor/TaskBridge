# Параллельные сессии TaskBridge

Дата: 27 сентября 2026. Этот документ фиксирует план и фактическую проверку.

## Цель и границы

Несколько независимых Pi-сессий должны одновременно выполнять ходы, когда
позволяют общий лимит, endpoint модели и рабочие каталоги. Сообщения одной
сессии остаются последовательными; steering относится только к её текущему
ходу. KMP и веб продолжают работать через существующие HTTP/SSE API.

Исходное состояние: `runtimes` уже содержит отдельный Pi на `taskId`, но один
`activeTaskId`, однопоточный `#pump()` и глобальный `#admit()` ограничивают весь
сервер одним ходом. В локальном `config.json` проекты работают без worktree;
этот пользовательский конфиг не изменяется автоматически.

## План реализации

- [ ] Выделить планировщик слотов: `runtime.maxWorking` (по умолчанию 3),
  `runtime.maxLive` (по умолчанию 6), `modelEndpoints[].maxConcurrent`.
  Консервативный лимит для управляемой локальной модели — один ход, пока
  реальная ёмкость endpoint не указана и не проверена.
- [ ] Заменить глобального владельца на набор работающих `taskId`. Один ход
  резервирует слот до терминального результата; освобождение происходит при
  успехе, ошибке, отмене, удалении и падении Pi. Повторное освобождение безопасно.
- [ ] Переписать pump: он стартует все подходящие задачи до исчерпания ёмкости,
  не ждёт завершения одной задачи и не создаёт второй ход в той же сессии.
  Неподходящая голова очереди не блокирует другие endpoint.
- [ ] Заменить глобальный `#admit` на блокировку по сессии и короткую
  атомарную проверку слотов. Одновременные запросы в разные сессии не должны
  получать ложный `BUSY`; `commandId` сохраняет дедупликацию.
- [ ] Для двух задач с общим `cwd` без worktree обеспечить сериализацию и
  объяснимый `WORKSPACE_BUSY`; разные worktree одного проекта могут работать
  параллельно. Не менять существующий `config.json` и не создавать worktree
  из грязной пользовательской копии без запроса.
- [ ] Отображать в KMP и вебе причину/позицию ожидания слота модели или
  рабочего каталога; `Stop` одной сессии не затрагивает другую.
- [ ] Добавить тесты реального перекрытия двух fake-Pi ходов, лимитов
  `maxWorking`/endpoint/workspace, порядка в одной сессии, отмены, восстановления
  после падения и двух одновременных HTTP-команд.
- [ ] Прогнать целевые тесты, `npm test`, KMP JVM-тесты и сборки Desktop/Android;
  при изменении клиента обновить portable `dist/TaskBridge`.

## Приёмка

При `maxWorking=2` два независимых удалённых хода имеют пересекающиеся интервалы
`RUNNING`. Третий ждёт, затем стартует сам. При лимите endpoint=1 два хода на
нём не пересекаются, а ход на другом endpoint проходит. Две задачи в общем
рабочем каталоге без worktree не пишут одновременно. Смена сессии в KMP не
останавливает уже работающий Pi. Результат, ограничения и команды проверки
фиксируются здесь после реализации.
